1-02 · Data Manipulation

fundamentals/1-02_data_manipulation.ipynb
cuDF
A GPU DataFrame library in RAPIDS. Here it is used with pandas-like operations so familiar tasks—loading, selecting, filtering, grouping, and creating columns—can execute on GPU-resident data.
DataFrame index
Labels that identify rows. The notebook uses .loc to select by label, rather than by numerical position; this distinction matters after sorting, filtering, or concatenating data.
Boolean mask
A same-length sequence of True/False values used to retain qualifying rows, such as counties north of Sunderland. It is the basis of vectorized filtering.
UDF
A user-defined function. .map() applies it element-by-element, while .apply() can work across a row or column; both are convenient but may be less efficient than built-in vectorized operations.

1-03 · Memory Management

fundamentals/1-03_memory_management.ipynb
Memory overhead
Memory beyond the logical values in a DataFrame. In this notebook, GPU usage can exceed the DataFrame’s reported size because CSV parsing and intermediate loading steps allocate additional buffers; leave headroom for these spikes.
memory_usage(deep=True)
A pandas estimate that includes the memory of objects referenced by string columns. Without deep=True, an object-string column can count pointers but understate the storage of the actual strings.
Downcasting
Changing a value to a smaller compatible type, such as int64 to int8 or float64 to float32. It reduces storage and memory traffic, but is valid only when the value range and required precision are preserved.
Categorical data
Discrete repeated labels stored as a category dictionary plus integer codes. It can save memory and speed operations for low-cardinality text fields, while preserving an optional meaningful order.

1-04 · GPU PyData Interoperability

fundamentals/1-04_interoperability.ipynb
CuPy
A NumPy-compatible GPU array library. The notebook uses it for numerical array work that sits naturally beside cuDF DataFrames, avoiding unnecessary transfers back to CPU NumPy.
British National Grid / OSGB
A projected coordinate reference system used in Great Britain. The latitude/longitude-to-OSGB converter yields easting and northing coordinates in metres, making local distance-based analysis more appropriate than operating directly on angular degrees.
Vectorization
Applying one operation to whole arrays at once instead of Python looping over individual records. In the grid converter, NumPy/CuPy expressions expose enough parallel work for the CPU/GPU library to execute efficiently.
Boolean array indexing
Using a Boolean array to select values from an array. It is the array analogue of DataFrame masking and is useful for filtering values that meet a computed condition.

1-05 · Grouping

fundamentals/1-05_grouping.ipynb
Split–apply–combine
The mental model for groupby: split records by a key, apply an aggregation or transformation within each group, then combine the results. Example: mean age per county.
Binning
Converting a continuous numeric variable into intervals, such as age bands. It simplifies summaries and plots but loses within-bin detail; bin boundaries therefore influence the conclusion.
transform vs apply
transform returns an output aligned to the original rows (for example, each person’s group mean); apply is more flexible and may return a reduced or reshaped result.
Pivot table
A cross-tabular summary that arranges groups into rows and columns and fills cells with an aggregation. It is a compact way to inspect how two categorical dimensions relate.

1-06 · Data Visualization

fundamentals/1-06_data_visualization.ipynb
Histogram
A count plot of observations in numeric bins. Unlike a bar chart of named categories, the choice of bin width changes the apparent shape of a continuous distribution.
Datashader
A rendering approach for very large point datasets: it aggregates data into display pixels before drawing. This prevents overplotting and keeps plots usable when one mark per row would be too slow or visually opaque.
cuxfilter dashboard
An interactive GPU-oriented visualization dashboard where views can be linked. Filtering or selecting in one view updates the others, supporting exploratory analysis of large data.

1-07 · Extract, Transform, Load

fundamentals/1-07_etl.ipynb
ETL
Extract, Transform, Load: obtain data from a source, clean/recode/derive analysis-ready fields, then write it to a target system or file. The notebook frames preprocessing as a reproducible pipeline rather than an ad hoc one-off step.
Parquet
A binary, columnar file format. It stores data by column with metadata and compression, so analytical reads can load only the needed columns and typically outperform repeatedly parsing CSV.
Columnar storage
Physical storage by column rather than by row. It is especially effective for analytical scans, aggregations, and compression because values of one field are adjacent and often similar.

1-08 · cuDF Polars

fundamentals/1-08_cudf-polars.ipynb
Eager execution
An operation runs immediately and returns a result. It is intuitive for interactive work, but each step commits to an execution plan before later operations are known.
Lazy execution
Operations build a query plan first; execution occurs when collect() is called. Polars can then optimize the whole plan, for example by pushing filters earlier or avoiding unused columns.
Execution graph
A directed representation of the planned data operations and their dependencies. Viewing it helps explain why lazy code can combine or reorder work while preserving the requested result.

1-09 · Dask cuDF

fundamentals/1-09_dask-cudf.ipynb
Partition
One chunk of a distributed DataFrame. Dask divides a larger-than-one-GPU dataset into partitions so workers can store and process them in parallel; partition size affects scheduling overhead and memory pressure.
Dask scheduler
The coordinator that turns a task graph into work assignments, respects dependencies, and places tasks on workers. It orchestrates computation; it is not itself where the DataFrame calculations happen.
LocalCUDACluster
A Dask cluster configuration that starts GPU-aware workers on the local machine, generally one per visible GPU, so Dask cuDF tasks can be distributed across them.
persist()
Materializes a lazy Dask collection into worker memory while retaining it as a distributed collection. Use it for an intermediate reused by later steps, but account for the cluster memory it occupies.

2-02 · Preparing Data for Graph Construction

fundamentals/2-02_prep_graph.ipynb
Graph, vertex, edge
A graph represents entities as vertices (nodes) and relationships as edges. Here, road junctions are vertices and road segments are edges; analysis depends on ensuring edge endpoint IDs match the vertex IDs.
Edge weight
A numeric cost attached to an edge. The notebook converts road length and road-type speed assumptions into travel time in seconds, so “shortest” can mean fastest rather than physically shortest.
Reindexing nodes
Replacing external node identifiers with a compact, consecutive ID range. It can make graph construction and GPU algorithms more efficient, provided the mapping is retained for interpretation.

2-03 · cuGraph Single-Source Shortest Path

fundamentals/2-03_cugraph.ipynb
Single-source shortest path (SSSP)
An algorithm that calculates the minimum total edge weight from one chosen source vertex to every reachable vertex. With time weights in this notebook, it estimates travel time across the road network.
Reachability
Whether a route exists between vertices under the graph’s connectivity and direction rules. An unreachable vertex has no finite path from the source and must not be interpreted as merely “very far away.”

2-04 · cuGraph as a NetworkX Backend

fundamentals/2-04_networkx_cugraph.ipynb
Backend dispatch
A mechanism that lets a NetworkX-style call execute through the accelerated nx-cugraph backend when compatible. The analysis code stays familiar while the computational implementation changes.
Centrality
A family of measures for a vertex’s structural importance. It is not a generic “importance” fact: each metric encodes a different network role and should be selected for a substantive question.
Betweenness / degree / eigenvector / PageRank / Katz
Betweenness counts routes passing through a node; degree counts direct connections; eigenvector and PageRank reward connections to influential nodes; Katz also counts longer walks but discounts them. The notebook compares these non-interchangeable meanings.

3-02 · K-Means

fundamentals/3-02_k-means.ipynb
K-means clustering
An unsupervised method that assigns each observation to one of a chosen number k of clusters, iteratively updating cluster centres to reduce within-cluster squared distances.
Centroid
The mean location of all points assigned to a K-means cluster. It is a mathematical centre, not necessarily an observed person or place, and is sensitive to scale and outliers.
Feature scaling
Putting input variables on comparable numerical scales before distance-based learning. Without it, a feature with a larger numeric range can dominate K-means distances regardless of its substantive relevance.

3-03 · DBSCAN

fundamentals/3-03_dbscan.ipynb
DBSCAN
Density-Based Spatial Clustering of Applications with Noise. It forms clusters from densely packed points, can discover non-spherical shapes, and labels points outside dense regions as noise.
eps and min_samples
eps is the neighbourhood radius; min_samples is the number of nearby points needed for a core point. They jointly define what density counts as a cluster, so their scale must match the units of the features.
Noise label
A DBSCAN assignment for an observation not density-connected to a cluster (commonly -1). It is an algorithmic result, not proof that a measurement is erroneous.

3-04 · Logistic Regression

fundamentals/3-04_logistic_regression.ipynb
Logistic regression
A supervised classifier that models the probability of a binary outcome, here infection, from predictors such as age or sex. Its linear score is transformed to the 0–1 probability scale with the logistic function.
Coefficient and odds
A coefficient changes the model’s log-odds, not probability by a fixed amount. Exponentiating it gives an odds ratio, whose interpretation still depends on the model specification and the other included predictors.
Train/test split
Holding out records that are not used for fitting, then evaluating the trained model on them. It estimates generalization to similar unseen data and guards against reporting in-sample performance as predictive ability.
Prevalence
The proportion of people with the outcome in a defined population or subgroup. A higher observed prevalence by age or sex is descriptive; it does not by itself establish a causal risk factor.

3-05 · K-Nearest Neighbors

fundamentals/3-05_knn.ipynb
K-nearest neighbors (KNN)
A distance-based method that retrieves the k closest reference points to each query. Here it maps hospitals to nearby road nodes; no model of the road network itself is learned.
Query vs reference data
Reference data is indexed for searching; query data is looked up against it. Keeping their roles and row indices straight is essential when interpreting returned distances and neighbour indices.
Euclidean distance
Straight-line distance in the supplied feature space. It is useful after suitable projection to metre-based grid coordinates, but it is not road travel distance and can ignore barriers or network constraints.

3-06 · XGBoost

fundamentals/3-06_xgboost.ipynb
XGBoost / gradient boosting
An ensemble method that builds decision trees sequentially, with each new tree correcting errors of the prior ensemble. It is powerful for tabular prediction but needs validation and careful parameter choices to avoid overfitting.
Hyperparameter
A setting chosen before or during fitting rather than learned directly from the training examples, such as tree depth, learning rate, or number of boosting rounds. Tune it using validation—not the final test set.
Feature importance
A model-derived summary of which predictors helped splits or reduced loss. It is useful for inspection but does not establish causality and can be distorted by correlated features or the particular importance definition.
ROC AUC
Area under the receiver-operating-characteristic curve: the probability that a randomly selected positive is scored above a randomly selected negative. It measures ranking discrimination across thresholds, not calibration or real-world utility by itself.

3-07 · Triton

fundamentals/3-07_triton.ipynb
Inference server
A service that receives model inputs and returns predictions. Triton packages a trained model for serving, handles requests, and supports multiple model backends; this is distinct from model training.
Model repository and configuration
Triton expects a directory organised by model name and version plus a config.pbtxt file. The configuration declares deployment-facing details such as inputs, outputs, batch limits, and backend settings.
Batch size and concurrency
Batch size is inputs per request; concurrency is simultaneous outstanding requests. Increasing either can improve GPU utilisation and throughput, but may raise latency or exceed memory limits.
Latency, throughput, p50/p95/p99
Latency is time per request; throughput is completed inferences per unit time. Percentiles summarize the latency distribution: p95, for instance, is the value at or below which 95% of measured requests finish.

3-08 · Multi-GPU K-Means with Dask

fundamentals/3-08_k-means_dask.ipynb
Multi-GPU training
Fitting one analysis across multiple GPUs by partitioning data and coordinating computation. It can expand capacity and speed, but gains depend on partition balance, communication, and whether the workload is large enough to amortize overhead.
Distributed K-means
K-means run over Dask-managed partitions. Worker-local calculations contribute to globally updated centroids, so the algorithm combines parallel local work with synchronization across the cluster.

4-02 · Find Clusters of Infected People

fundamentals/4-02_find_infected.ipynb
Spatial cluster
A geographically concentrated group of cases. In the project, DBSCAN identifies dense patterns in projected grid coordinates; a detected cluster is a pattern to investigate, not an explanation for why infection occurred.
Largest cluster
The cluster with the greatest number of assigned observations. It is different from the geographically largest area or the cluster with the highest local density, so state the criterion explicitly.

4-03 · Identify Nearest Health Facilities

fundamentals/4-03_nearest_facilities.ipynb
Easting and northing
The horizontal and vertical coordinates of a projected grid. In the British National Grid conversion used here, their metre-based scale permits KNN to compute an interpretable straight-line proximity measure.
Nearest facility index
The integer returned by kneighbors that identifies the closest row in the facilities reference DataFrame. It must be used to join back to facility metadata such as OrganisationID; resetting indexes prevents accidental row-label mismatches.

4-04 · Identify Risk Factors for Infection

fundamentals/4-04_identify_risk_factors.ipynb
Stratification
Calculating a summary within subgroups, such as employment code and sex. It checks whether an aggregate pattern is consistent across a relevant grouping and can reveal differences masked by the overall rate.
Risk factor
A characteristic associated with a higher outcome rate in a defined analysis. The project’s grouped infection rates identify candidates for further investigation; observational association alone does not prove that employment or sex causes infection.
