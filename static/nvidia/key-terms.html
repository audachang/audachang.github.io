NVIDIA Accelerated Computing Stack — Key Terms

Technical terms and acronyms organized by stack layer, from easiest to use to maximum performance.

Fundamentals of Accelerated Data Science

How to read this stack

The NVIDIA accelerated computing stack is a series of layers trading ease of use against control and performance. The top layers require zero or minimal code changes but hide GPU details; the bottom layers require writing C++/CUDA but offer maximum performance. Most data science work happens in the top three layers.

Foundations

(terms behind the whole stack)
These terms appear in every layer below — make sure they are solid first.
TermFull nameDefinition
GPU Graphics Processing Unit A processor with thousands of small cores designed for massively parallel computation. Originally built for graphics, now the workhorse of accelerated data science and AI.
CPU Central Processing Unit A processor with few but powerful cores, optimized for sequential and general-purpose tasks. In accelerated computing, the CPU orchestrates work and the GPU executes the parallel parts.
API Application Programming Interface A defined interface through which software components communicate. It specifies the functions, inputs, outputs and rules a library or service exposes, so a program can use it without knowing its internal implementation.
CUDA Compute Unified Device Architecture (original expansion; now used simply as a name) NVIDIA's parallel computing platform and programming model — the foundation every library in this stack is built on. It lets programs define work that runs across thousands of GPU threads.
kernel — (general CUDA concept) A function that runs on the GPU, executed simultaneously by many threads. "Writing a kernel" means writing the code each GPU thread will run.
RAPIDS — (brand name, not an acronym) NVIDIA's open-source suite of GPU-accelerated data science libraries (cuDF, cuML, cuGraph, cuVS, RMM…). Its APIs deliberately mirror pandas, scikit-learn and NetworkX to minimize the learning curve.

1 · Zero Code Change: Acceleration Plugins

(no-code change)
Load a plugin or switch a backend and existing pandas / NetworkX / Spark / scikit-learn code runs on the GPU. Unsupported operations automatically fall back to the CPU. Easiest entry point, least control.
TermFull nameDefinition
cudf.pandas cuDF pandas accelerator mode cuDF's zero-code-change mode. Enabled with %load_ext cudf.pandas (Jupyter) or python -m cudf.pandas, it intercepts pandas API calls, runs supported operations on the GPU, and silently falls back to CPU pandas for the rest.
nx-cugraph Accelerated NetworkX (cuGraph backend for NetworkX) A GPU backend plugin for NetworkX, the most popular Python graph-analysis library. Once installed, algorithms such as PageRank and shortest paths dispatch to cuGraph on the GPU with no code changes.
RAPIDS Spark Accelerator RAPIDS Accelerator for Apache Spark A plugin for Apache Spark that transparently moves Spark SQL and DataFrame operations onto GPUs, accelerating large-scale ETL and query workloads without changing Spark application code.
Array-API backed scikit-learn scikit-learn with Python Array API standard support Scikit-learn estimators that support the Array API standard can accept GPU arrays (e.g., CuPy arrays or PyTorch tensors) directly, so the same estimator code computes on the GPU with essentially no changes.

2 · Hybrid CPU/GPU Libraries

(minimal change)
One API that runs on either CPU or GPU — usually just a device flag away (e.g., device="cuda" ). Develop anywhere, accelerate when a GPU is present.
TermFull nameDefinition
PyTorch — (name) Meta's deep learning framework built on tensor computation and automatic differentiation. Moving work to the GPU is one call: .to("cuda").
FAISS Facebook AI Similarity Search A library for efficient similarity search and clustering of dense vectors, with both CPU and GPU indexes. Widely used in recommender systems and retrieval-augmented generation (RAG).
TensorFlow — (name) Google's end-to-end machine learning framework. It automatically places operations on a GPU when one is available.
XGBoost eXtreme Gradient Boosting The leading gradient-boosted decision tree library for tabular data. GPU training is enabled with a single parameter (device="cuda").
cuML-CPU cuML CPU execution mode cuML's CPU execution capability: the same cuML estimator code can run on machines without a GPU (e.g., a laptop) and later run unchanged, accelerated, on a GPU system.
Dask — (name) A Python framework for parallel and distributed computing. It partitions pandas/NumPy/cuDF workloads and schedules them across cores or cluster nodes; combined with RAPIDS (dask-cudf) it scales to multiple GPUs.
PySpark Python API for Apache Spark The Python interface to Apache Spark, the distributed big-data processing engine. Pairs with the RAPIDS Spark Accelerator (layer 1) for GPU acceleration.

3 · GPU Python Libraries

(GPU Python code)
Python libraries written explicitly for the GPU: data stays in GPU memory end-to-end, giving more performance and control — but the code assumes a GPU is present.
TermFull nameDefinition
cuDF CUDA DataFrames RAPIDS' GPU DataFrame library with a pandas-like API. Loading, filtering, joining and group-by aggregation all execute in GPU memory.
cuML CUDA Machine Learning RAPIDS' GPU machine learning library with a scikit-learn-like API: regression, clustering (e.g., k-means, DBSCAN), dimensionality reduction (PCA, UMAP), random forests and more.
cuGraph CUDA Graph analytics RAPIDS' GPU graph analytics library — PageRank, community detection, shortest paths and more — and the engine behind the nx-cugraph NetworkX backend.
cuVS CUDA Vector Search RAPIDS' library for vector search and clustering on the GPU, providing approximate nearest neighbor (ANN) indexes such as CAGRA and IVF-PQ — the machinery behind GPU-accelerated vector databases and RAG.
RMM RAPIDS Memory Manager The centralized GPU memory management layer for RAPIDS: memory pools and pluggable allocators that let cuDF, cuML and CuPy share GPU memory efficiently instead of each allocating on its own.
CuPy — (name blends CUDA + NumPy/Python) A NumPy/SciPy-compatible array library for CUDA GPUs. For much code, acceleration is as simple as replacing import numpy as np with import cupy as cp.
Numba — (name) A just-in-time (JIT) compiler for Python: decorators such as @jit compile numeric Python functions to fast machine code at run time, on CPU — and on GPU via its CUDA target (layer 4).
OpenAI Triton — (name) An open-source Python-like language and compiler for writing custom high-performance GPU kernels. Heavily used by PyTorch 2's torch.compile.

4 · Python/CUDA Libraries

(hybrid Python / CUDA code)
Write actual CUDA kernel code from inside Python — Python's convenience with CUDA-level control, for operations no library provides.
TermFull nameDefinition
CuPy RawKernel CuPy raw CUDA kernel interface A CuPy feature for embedding native CUDA C++ kernel source as a Python string; CuPy compiles it at run time and launches it on the GPU.
Numba CUDA Numba CUDA target (@cuda.jit) Numba's CUDA mode: write CUDA kernels in Python syntax with the @cuda.jit decorator, with direct access to GPU programming concepts such as thread indexing and shared memory.
Cython wrappers for CUDA Cython — C-Extensions for Python Cython compiles Python-like code to C/C++, and is commonly used to wrap CUDA C++ libraries so they can be called from Python with minimal overhead.

5 · C++/CUDA High Level

(high-level C++/CUDA code)
High-level C++ abstractions: compose high-performance GPU programs without writing every kernel from scratch. The RAPIDS libraries themselves are built on this layer.
TermFull nameDefinition
RAFT Reusable Accelerated Functions and Tools A CUDA C++ library of fundamental, widely-used primitives — linear algebra, clustering, nearest-neighbor building blocks — shared as the common foundation under cuML, cuVS and cuGraph.
CCCL CUDA Core Compute Libraries NVIDIA's umbrella project that unifies Thrust, CUB and libcudacxx (the CUDA C++ standard library) into a single core C++ library suite.
Thrust — (name) A C++ parallel algorithms library modeled on the C++ STL — sort, reduce, scan and friends — producing efficient GPU code from high-level calls, no hand-written kernels required.
CUB CUDA UnBound (commonly cited expansion; current docs simply use "CUB") A library of reusable, high-performance primitives at the warp, block and device level — the building blocks used when writing custom CUDA kernels.

6 · CUDA Toolkit

(C++/CUDA code and kernels)
The foundation: the CUDA compiler, runtime, debugging/profiling tools, and heavily optimized math libraries. Maximum performance ceiling, highest development cost.
TermFull nameDefinition
CUDA Toolkit CUDA development toolkit The complete development kit for CUDA: the nvcc compiler, CUDA runtime, debuggers (cuda-gdb), profilers (Nsight) and the math libraries listed below.
cuBLAS CUDA Basic Linear Algebra Subprograms The GPU implementation of BLAS: dense linear algebra (matrix multiplication / GEMM and friends). The core numerical engine behind deep learning frameworks.
cuDNN CUDA Deep Neural Network library Highly tuned GPU primitives for deep neural networks — convolution, pooling, normalization, attention. PyTorch and TensorFlow rely on it as their GPU backend.
cuSolver CUDA Solver library GPU-accelerated matrix factorizations and solvers: LU, QR, SVD, eigenvalue problems — the LAPACK-like layer of the toolkit.
cuSPARSE CUDA Sparse matrix library GPU-accelerated sparse matrix operations (e.g., sparse matrix–vector multiplication, SpMV), used in graph computation and scientific computing where most matrix entries are zero.
